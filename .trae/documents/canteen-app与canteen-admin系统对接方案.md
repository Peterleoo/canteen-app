# canteen-app与canteen-admin系统对接方案

## 1. 项目现状分析

### canteen-app (用户端)
- **技术栈**：React + Vite + Zustand + React Router
- **主要功能**：菜单浏览、购物车管理、订单管理、地址管理
- **数据存储**：Supabase (productService.ts)
- **当前问题**：部分数据模型与管理端不一致，API调用逻辑分散

### canteen-admin (管理端)
- **技术栈**：React + Vite + RBAC权限系统
- **主要功能**：商品管理、订单管理、用户管理、食堂管理、权限管理
- **数据存储**：Supabase (完整的API服务层)
- **优势**：完善的权限控制、统一的API设计、丰富的管理功能

## 2. 系统对接目标

1. **数据一致性**：统一两个项目的数据模型和数据库结构
2. **API标准化**：实现统一的API调用方式和接口设计
3. **功能互补**：管理端提供数据管理，用户端提供用户交互
4. **可扩展性**：支持未来功能扩展和业务增长

## 3. 具体对接方案

### 3.1 数据模型对齐

**核心数据模型统一**：
- 商品模型 (Product)
- 订单模型 (Order)
- 用户模型 (User)
- 食堂模型 (Canteen)
- 地址模型 (Address)

**实施步骤**：
1. 统一TypeScript类型定义，确保枚举值一致
2. 对齐数据库表结构，添加必要的关联关系
3. 优化数据字段命名，统一使用snake_case (数据库) 和 camelCase (前端)

### 3.2 API服务层整合

**共享API服务**：
- 将API调用逻辑抽象为独立的服务层
- 实现统一的错误处理和日志记录
- 支持API版本控制

**实施步骤**：
1. 重构canteen-app的API调用逻辑，参考管理端的设计
2. 统一API请求格式和响应格式
3. 实现API的权限控制和认证机制

### 3.3 数据库设计优化

**新增/修改数据库表**：
- **orders表**：添加user_id、canteen_id等关联字段
- **order_items表**：存储订单商品明细
- **users表**：完善用户信息，添加统计字段
- **canteens表**：添加配送配置、营业时间等字段

**实施步骤**：
1. 设计数据库表结构，添加必要的索引
2. 编写数据库迁移脚本
3. 测试数据库查询性能

### 3.4 新接口开发

**核心接口开发**：
1. **商品接口**：
   - GET /api/products - 获取商品列表
   - GET /api/products/:id - 获取商品详情
   - POST /api/products - 创建商品
   - PUT /api/products/:id - 更新商品
   - DELETE /api/products/:id - 删除商品

2. **订单接口**：
   - GET /api/orders - 获取订单列表
   - GET /api/orders/:id - 获取订单详情
   - POST /api/orders - 创建订单
   - PUT /api/orders/:id/status - 更新订单状态

3. **用户接口**：
   - GET /api/users - 获取用户列表
   - GET /api/users/:id - 获取用户详情
   - POST /api/users - 创建用户
   - PUT /api/users/:id - 更新用户

4. **食堂接口**：
   - GET /api/canteens - 获取食堂列表
   - GET /api/canteens/:id - 获取食堂详情
   - POST /api/canteens - 创建食堂
   - PUT /api/canteens/:id - 更新食堂

### 3.5 系统集成测试

**测试内容**：
1. 数据一致性测试：确保管理端修改的数据能实时同步到用户端
2. API调用测试：测试所有API接口的正确性和性能
3. 权限控制测试：确保用户端只能访问其有权限的数据
4. 异常情况测试：测试系统在异常情况下的处理能力

**实施步骤**：
1. 编写集成测试用例
2. 搭建测试环境
3. 执行测试并修复问题
4. 编写测试报告
